# 建议架构

## 数据流

```text
浏览器上传
  → 临时私有对象存储
  → 视频元数据与解码检查
  → 代表性动作阶段提取
  → 动作身份与画面质量检查
  → 安全规则
  → 报告生成
  → 用户确认后的训练摘要
  → 到期自动删除原视频与派生画面
```

## 服务边界

- Web：上传、训练记录、报告阅读和删除控制。
- API：授权、任务创建、状态查询和报告读取。
- Worker：视频解码、阶段提取和动作证据生成。
- Rule layer：疼痛、失控、证据不足与进阶条件。
- Report layer：把可见证据转换为教练式语言，不新增事实。
- Storage：用户级隔离、短期媒体保留和审计记录。

## 报告契约

单动作报告至少包含动作身份、证据置信度、画面限制、安全优先级、可见证据、原因、下一步动作、已知重量/次数和具体进阶条件。

生产版本应把“用户填写”“视频可见证据”“历史对比”和“模型推断”分别存储，禁止在展示层合并为无来源结论。
